AGENTS.md・README.md・docs/index.md・対象ソースと近接文書を読む。既存のREADME・docsを仕様の正本として読み、矛盾は根拠とともに報告する。
git statusと差分、現在ブランチ、既存の作業を確認する。Git未初期化ならその状態を報告し、無断で初期化しない。

## ローカル調査結果（2026-10-20）

GitHubプロフィール表示用READMEとassets/SVG。www・サーバー転送はない。snake.ymlは定期生成してoutputブランチへ書き込む。

## 案件固有の確認

READMEは公開プロフィールそのものなので内部の運用記録を本文に混ぜない。製品紹介の公開状態、プロフィール文、リンク、SVGのalt・ライト/ダーク表示、素材クレジットを確認する。

## 品質・計測

git diff --check。SVGの構文と参照、READMEの表示を確認する。外部画像の参照先を勝手に他ブランチへ変更しない。
UIの変更はPC/スマホ、文字切れ・画像・リンク・主要CTA・キーボード操作・Console/Networkを確認する。新規ページの計測は既存方針を確かめて引き継ぎ、他案件のIDを流用しない。ローカルでは本番計測への送信を止め、個人情報をイベントに含めない。設置・送信・管理画面受信は別の状態とする。未実行を検証済みにしない。

## 公開・外部操作

GitHubへのpushが公開プロフィールに反映される。既存snake.ymlはcontents:writeでoutputに生成物を保存するため、手動起動は公開操作として扱う。Webサイト用deploy-up.shを新設しない。
文書整備では公開READMEの紹介文・SVG・Actionsを変更しない。GitHub tokenや実プロフィール情報を検査ログへ追加しない。
公開依頼時は対象・環境・復元手段を確定し、実在する検査とドライランの出力・終了コードを確認する。対象外の変更を含めない。検証後に変更した場合は再検査する。削除同期・force push・全体再転送を自動リカバリに使わない。公開後のURL・動作・必要なヘッダーや計測は別途検証する。

## 文書・完了報告

docsは原則Git管理。資料画像と配信用画像を分け、相対リンクを使う。既存の目次を更新し、リンク・画像・目次からの到達性を確認する。重複は候補として報告し自動削除しない。仕様と実装の意味の照合はlintとは別に行う。重要判断のみADRを追加する。
既存CIを先に確認し、文書検査のために公開ジョブを起動しない。新依存や大規模CI変更は必要性を整理する。今回は自動品質CIの新設は行わず、既存機構と改善候補をレポートへ記録する。
変更ファイル・検査範囲と結果・未確認・公開状態を報告する。
